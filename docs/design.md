# Grok Remote 实施方案

本文记录已拍板的第一版范围和做法，供实现时对照。未写入「已定」的条目，实现前再确认，不擅自发挥。

对照来源：Grok Remote 与 Codex Remote 独立部署、使用各自的前后端和入口；Grok Remote 的界面以 Codex Remote 为基线保持布局、视觉和通用交互一致。Worker 生命周期采用按需进程模型（Grok 用语替换 Codex 的 thread / full access）；本仓库讨论结论。

## 1. 产品

单用户、自托管 PWA。在手机或电脑上控制这台 Linux 主机上的 Grok Build CLI。

要解决的是高延迟下手感：字在浏览器里编完再发。发出并被后端接受后，页面可以关掉；本轮由后端 Worker 继续跑。

不是官方产品，不是多人账户。部署者是唯一受信任的使用者。

## 2. 已定

| 事项 | 结论 |
| --- | --- |
| 应用边界 | 与 Codex Remote 是两个独立项目、服务和入口，不合并运行时 |
| UI 基线 | 布局、视觉和通用交互与 Codex Remote 保持一致；两边 UI 修改应同步 |
| 功能 | Codex Remote 里有、Grok 也有的能力都要有；名字跟 Grok，不跟 Codex 对齐 |
| 本机端口 | 8788（Codex Remote 占用 8787） |
| 监听 | 只绑 `127.0.0.1`；远程走 Tailscale Serve 或公网 HTTPS 反代 |
| 环境变量 | `GROK_REMOTE_*` |
| 项目白名单 | 与 Codex Remote 共用同一份 `projects.json`，用环境变量指向路径 |
| 会话整理 | 归档和回收站都用本应用本地标记（Grok 没有归档接口）；回收站 30 天后永久删除。没发过第一条消息的 pending 会话刷新后不保留 |
| 审批按钮 | 本次允许 / 拒绝 |
| 权限开关 | 名称用 `always-approve`，不要写成 full access |
| 工具展示 | 与 Codex Remote 同类：聊天里给命令卡片，不把审批做成看代码 |
| 命令标题 | 只显示前面一小段加省略号，点开看全文 |
| 进程模型 | 按需会话 Worker，第一版就按这个骨架做 |
| 上传 | 复用共享 `ai-remote-upload` 服务、附件 ID、一次性票据和任务租约；不在本仓库复制存储层 |

## 3. 第一版不做

- 在 Grok Remote 内复制一套附件存储、清理或公网上传服务
- 和 Codex Remote 合并成同一个运行时前端或共用整套 Node 后端
- 每个会话常驻一个 Grok 进程（HAPI 那种，关掉页面或归档才释放）
- 全站共用一个长驻 `grok agent`、所有会话都挂在上面
- 浏览器直连 `grok agent serve`
- 每条消息用 `grok -p` 起一个一次性进程（接不上双向审批）

附件存盘由模型无关的共享 `ai-remote-upload` 服务负责，可供 Grok Remote、Codex Remote 和其它 Remote 复用。Grok Remote 只实现自己的鉴权入口、任务租约和 ACP 输入映射。

## 4. 数据路径

```text
手机或电脑浏览器 PWA
  → HTTPS（Tailscale Serve 或公网反代）
  → 127.0.0.1:8788 上的 Grok Remote（共享 Node 后端）
  → Unix socket 上的共享 ai-remote-upload（仅附件）
  → 仅在需要执行时：按需 Worker = grok agent stdio（ACP JSON-RPC）
  → Grok 原生会话 ~/.grok/sessions/<按工作目录分组>/<session-id>/
```

浏览器只看见为这个 PWA 准备的小协议。不要把 ACP、文件系统、Git、终端能力暴露给浏览器。

共享后端只做：鉴权、静态 PWA、WebSocket、项目白名单、会话登记、事件持久化、权限转发、Worker 启停。不为每个会话复制一套 HTTP 服务。

## 5. 配置

| 环境变量 | 作用 |
| --- | --- |
| `GROK_REMOTE_TOKEN` | 浏览器 WebSocket 登录令牌，至少 32 个字符 |
| `GROK_REMOTE_PORT` | 回环端口，默认 8788 |
| `GROK_REMOTE_ALLOWED_ORIGINS` | 额外允许的 Origin，逗号分隔；通常留空 |
| `GROK_REMOTE_PROJECTS_CONFIG` | 项目白名单文件路径 |
| `GROK_BIN` | `grok` 可执行文件；默认从 `PATH` 查找 |
| `AI_REMOTE_UPLOAD_SOCKET` | 共享上传服务 Unix socket；默认 `~/.local/share/ai-remote/upload.sock` |

项目白名单可与 Codex Remote 共用同一份配置，也可以单独提供；部署时由 `GROK_REMOTE_PROJECTS_CONFIG` 指向实际配置文件。配置文件声明一个或多个项目根目录，网页里的项目是根目录下的第一层文件夹。

浏览器只看到项目 ID 和名称，拿不到绝对路径。会话的 cwd 由后端根据项目 ID 再解析。真实令牌、本机账号和实际项目路径不进 git。

## 6. Worker

这是第一版主路径，不能先做成「一轮绑死在一条 WebSocket 上」再改。

### 6.1 何时有进程

- 用户发消息（或必须跑 Grok 才能完成的命令）且后端已经 `accepted`：若该会话没有 Worker，则启动一个。
- 本轮结束，且该会话消息队列为空：Worker 退出，不常驻。
- 只打开会话看历史、翻列表、搜索：不启动 Worker。
- 同一会话同时最多一个 Worker；多条已接受的消息按顺序排队，不能并发改同一个 Grok session。

Worker 是独立进程组里的 `grok agent stdio`，不是 Node `worker_threads`，也不是「每个聊天会话从打开到归档一直挂着」。同时跑几轮，才同时有几个 Grok 进程。做完就退。

### 6.2 交互

1. 前端提交消息，带上唯一 `clientMessageId`，避免重试重复执行。
2. 后端接受后返回 `accepted` 和 `turnId`。此时可以关页面。
3. Worker 在后台跑；后端持续写入输出事件和本轮状态。
4. 再打开页面：接上正在流式的输出，或直接读已经完成的回复。事件带可恢复的顺序标识，从上次读到的位置续。
5. 下次再发消息：若 Worker 已退，用保存的 Grok session id 再起 Worker 并恢复。

一轮不要绑在某一个标签页或某一台设备上。

### 6.3 权限与断线

- 以「是否至少有一个有效前端连接」为准。任意在线客户端都可以处理审批。
- 最后一个前端断开后，留 10 秒宽限期（切 App、刷卡、网络抖、短暂重载不要误杀）。
- 普通 / 手动权限：
  - 10 秒内回来：审批照常。
  - 宽限期结束仍无前端：拒绝待处理审批，并且取消**整轮**，不能只拒一个工具还让模型换办法继续。
  - 留下已有部分回复、审批摘要、中断原因，本轮标为 `interrupted`。
- `always-approve`：没人看着也可以自动处理可授权的工具，本轮跑完再退 Worker。
- `always-approve` 不能代答选择题、验证码、登录授权等必须人来的输入。这类出现且没有前端在线：同样中止本轮。Grok 的 `ask_user_question` 按这一类处理。
- 终止 Worker 前：先对 Grok 回答拒绝并 `session/cancel`，等原生会话落盘；超时再杀整个进程树。
- 用户再打开该会话时，必须能看出上次是因为没人处理权限或需要用户输入而中止；要继续就自己发「继续」。

权限模式作为本轮持久化配置保存，不要只记在当前 WebSocket 上。

快捷栏按钮文案用 `always-approve`。手机窄屏那一行可横滑；若以后字太长再改图标。

### 6.4 附件与租约

- 浏览器在已认证 WebSocket 上申请票据，并同源流式上传原始字节；票据固定绑定 `grok + projectId + sessionId`。
- 消息的幂等记录同时保存正文与附件 ID；相同 `clientMessageId` 不能换正文或附件重用。
- 后端接受带附件的消息前创建租约，排队、执行和等待审批期间每 5 分钟续期，完成、失败或中断后释放。
- 公开事件只保存附件 ID、原始文件名和其它公开元数据；共享存储路径和附件正文只在本机适配过程中使用。
- 图片使用 ACP `image` 内容块；UTF-8 文本使用 ACP 内嵌文本资源；其它二进制使用 ACP blob 资源。不能把成功上传等同于模型已经理解内容。

### 6.5 状态

后端至少区分：`queued`、`running`、`waiting_for_permission`、`completed`、`interrupted`、`failed`。

前端断开不得丢掉已接受的消息、部分回复、工具事件、最终回复。

### 6.6 资源

- 活动 Worker 要有明确上限。到上限时告诉用户并拒绝或排队，禁止偷偷停掉别的会话。
- 启动前看可用内存，低于阈值就明确反馈，避免把 VPS 打进持续换页或 OOM。
- 具体上限、阈值、到限后是拒绝还是排队：实现前再定，见第 10 节。

## 7. 会话与命令

- 列表分三视图：最近会话 / 已归档 / 回收站。新建、恢复、归档、移入回收站、从回收站恢复。界面与 Codex Remote 对齐。
- 归档和回收站只处理已经真正建出来的 Grok 会话。没发过第一条消息的 pending 会话刷新后不保留，也不进归档或回收站。
- 正在运行的会话不能归档或移入回收站。
- 回收站条目 30 天后自动永久删除（Grok 磁盘和本应用记录一起删）。浏览器里没有单独的「立刻永久删除」按钮。
- 会话正文以 Grok 磁盘为准；本应用额外保存：进行中的一轮、事件日志、权限模式、原生 session id、归档和回收站标记。不要复制整份对话当唯一真相。
- 斜杠命令用 Grok 的名字和语义。实现时按当时 Grok CLI 已有命令列一份目录，不把 Codex 的 `/permissions`、`/usage` 等名字硬搬过来。能对上的能力都要有，例如 `/compact`、`/model`、`/rename`、`/rewind`、`/session-info`（可与 `/status` 同义）、`/plan`、`always-approve`。Grok 另有的（如 `/effort`）按 Grok 做。
- 登录后从后端读命令目录，不要把名单写死在每台设备的缓存里。

## 8. 前端

独立部署的 PWA：登录、项目选择、会话列表、本地编辑后发送、流式显示、安全 Markdown 子集、斜杠菜单、心跳与重连。界面以 Codex Remote 当前前端为基线；Logo、产品名称和已确认的 Grok 能力差异可以不同，其他 UI 差异需先确认。

约束：

- 令牌只放 `localStorage`，用于刷新和重连。
- 登录或重连后只加载会话列表，不自动打开上次会话。
- 回复流式阶段先纯文本，整段结束后再渲染一次 Markdown；不执行原始 HTML，图片语法不当成自动加载的 `<img>`。
- 命令卡片标题截断加省略号，点开看完整命令和输出。输出过长可截断，标题必须截。
- 不给浏览器主机绝对路径、原始审批命令细节超出 Codex Remote 同类范围的内容、ACP 内部 id。
- 同一项目同时只允许一个设备控制进行中的任务；其它设备可以看推送，但不能同时开停该任务。此项若与「任意在线客户端都能点审批」冲突，审批仍按第 6.3 节（有人在即可点），任务的开始/停止仍受项目锁约束。

## 9. 安全

- 服务只听回环。入口挂了，也不会自己绑到公网网卡。
- WebSocket 校验 Origin（与 Host / `X-Forwarded-Host` 同源，或 `GROK_REMOTE_ALLOWED_ORIGINS`）。
- 令牌定时安全比较；环境文件权限收紧。
- 项目必须落在白名单根目录的第一层文件夹内；恢复会话时核对 Grok 返回的 cwd，防止跨项目打开。
- ACP 客户端不要向 Grok 声明可代读代写任意文件的 `fs` / `terminal` 能力。文件和命令走 Grok 自己的工具、项目 cwd、主机上的 Grok 权限与沙箱。
- 操作系统抛出的带绝对路径的错误只写服务日志；浏览器只收到不含路径的说明。

## 10. 实现前仍需再定

这些不影响「第一版按 Worker 骨架做」，但写代码碰到时要先问，不要默认选：

1. Grok session id 的保存与 `session/load` 恢复方式；中断后的会话是否总能可靠接着跑。
2. Worker 本轮结束后是立刻退出，还是留一个很短的复用窗口。
3. 活动 Worker 上限、最低可用内存、到限时拒绝还是排队。
4. 10 秒宽限期用连接数、心跳还是客户端租约来算。
5. grok-remote 自己重启后，`queued` / `running` / `waiting_for_permission` 是恢复还是标成中断。

## 11. 验收（第一版）

- 令牌登录；只能看到白名单里的项目。
- 可新建、列出、打开、归档、移入回收站、恢复会话；回收站显示剩余天数，到期永久删除。
- 消息得到 `accepted` 后立刻关页面，本轮仍能完成并保存。
- 关页面不会直接杀掉正在跑的 Worker。
- 普通权限：无人在线且超过 10 秒宽限期，待审批被拒绝、整轮取消，再打开能看到中断说明。
- 10 秒内重连，不会误拒正在等的审批。
- `always-approve`：前端断开后可授权操作仍继续，跑完 Worker 退出。
- 需要人回答的问题在无前端时中止本轮。
- 重连可续上事件或读完整结果，不因重试而把已接受的消息跑两遍。
- 可上传、移除并发送多个附件；浏览器和公开事件看不到共享存储路径或附件正文。
- 真实图片和 UTF-8 文本附件能被 Grok 按内容理解；不支持的二进制格式给出明确结果，不把落盘成功冒充为理解成功。
- 同一会话不会两个 Worker 一起跑；结束后不留 Grok 子进程。
- 只看历史时，进程列表里不应出现该会话的 `grok agent`。
- 命令标题过长被截断，点开可见全文。
- 本机 `8788` 健康检查可用；与 Codex Remote 的 `8787` 同时存在互不影响。

## 12. 实现顺序建议

1. 共享 HTTP/WebSocket 后端：令牌、Origin、静态 PWA、白名单、健康检查。
2. 会话登记与 Grok session id：列表、新建、打开历史（不启动 Worker）、归档、回收站。
3. Worker 管理：启动、队列、进程组、退出、内存/数量门闩。
4. 发消息：`accepted`、事件持久化、重连续传、关页面不中断。
5. 审批与 `always-approve`、断线宽限期、整轮取消。
6. 斜杠命令目录与 Grok 扩展方法。
7. 前端会话壳、流式缓冲、Markdown、命令卡片截断。
8. 按第 11 节做浏览器与进程验收。

未完成第 3–5 步之前，不要用「一个长驻 Grok 进程撑所有会话」当临时实现，否则后续等于重写。
